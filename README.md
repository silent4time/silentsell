# mirza_vali Pro

ربات فروش و مدیریت اشتراک VPN برای **تلگرام** و **بله**

**نسخه:** 5.0.24 — تغییرات هر نسخه در [CHANGELOG.md](CHANGELOG.md)

> **نکته:** مسیر نصب پیش‌فرض `/home/mirza_vali_pro` است.
>
> **تازه‌های 5.0.24:** بازنویسی کامل اتصال کانکتیکس طبق مستندات رسمی API فروشنده؛ تمدید فقط با یک درخواست (بدون خطر خرید دوباره)، حجم و انقضای دقیق و لینک ساب واقعی.

---

## معرفی

`mirza_vali Pro` یک ربات کامل برای فروش سرویس VPN است که همزمان روی **تلگرام** و پیام‌رسان **بله** کار می‌کند. خرید، پرداخت، تحویل خودکار سرویس، کیف پول و پنل مدیریت ادمین در یک سیستم یکپارچه پیاده‌سازی شده است.

این پروژه بر پایه ربات متن‌باز **میرزا** توسعه یافته و برای استفاده عملی در فروش اشتراک سفارشی شده است.

## لایسنس Pro

ربات پرو با یک کلید لایسنس کار می‌کند که از فروشنده تهیه می‌شود. کلیدها در سایت فروشنده با افزونهٔ وردپرس **«مدیریت لایسنس ربات میرزا ولی»** صادر و تمدید می‌شوند و ربات آدرس سرور لایسنس را به‌صورت داخلی دارد؛ لازم نیست آدرسی وارد کنید.

| مورد | توضیح |
|------|--------|
| قفل | فقط روی **دامنهٔ** ربات (همان `$domainhosts`) |
| مدت | ۱ تا ۱۲ ماه |
| انقضا | فقط **فروش** متوقف می‌شود؛ خود ربات آنلاین می‌ماند |
| هشدار | حدود ۷ روز مانده به انقضا و هنگام انقضا، پیام برای ادمین |
| قطع سرور لایسنس | تا **۹۶ ساعت** با آخرین وضعیت ذخیره‌شده کار می‌کند |

### ثبت کلید

1. در ربات وارد منوی مدیریت شوید.
2. دکمهٔ **🔑 لایسنس ربات** ← **ثبت / ویرایش کلید** را بزنید و کلید را بفرستید.
3. برای دیدن وضعیت (اعتبار، روزهای باقی‌مانده، تاریخ انقضا) دستور زیر را بفرستید:

```text
/license
```

> **نکته:** کلید فقط روی دامنه‌ای کار می‌کند که برایش صادر شده است. اگر دامنهٔ ربات را عوض می‌کنید، قبلش از فروشنده بخواهید دامنهٔ کلید را تغییر دهد.

## پنل ایلان (Eylan) — نحوه استفاده

پنل ایلان چند پروتکل را روی یک سرور پشتیبانی می‌کند (OpenVPN، WireGuard، L2TP/IPsec، Cisco AnyConnect و حالت ترکیبی Multi).

**نکته مهم:** در ربات، برای **هر نوع VPN باید یک پنل جداگانه** تعریف شود. نباید همه پروتکل‌ها را با یک ردیف پنل بفروشید.

### مراحل پیشنهادی

1. در پنل مدیریت ادمین، برای هر پروتکل یک پنل با نوع **EylanPanel** بسازید.
2. آدرس API و کلید API (همان فیلد رمز پنل) را وارد کنید.
3. در فیلد **Inbound / inboundid** یکی از مقادیر زیر را دقیقاً بنویسید:

| مقدار inboundid | خروجی برای کاربر |
|-----------------|------------------|
| `openvpn` | فایل‌های `.ovpn` + صفحه کاربری |
| `wireguard` | فایل‌های `.conf` (+ QR در صورت پشتیبانی) |
| `l2tp` | سرور، یوزرنیم، رمز، Shared Key (PSK) |
| `cisco` | سرور، یوزرنیم، رمز |
| `multi` | ترکیب پروتکل‌های فعال (OVPN + WG + L2TP + Cisco) |

4. برای هر پنل یک **محصول** جدا بسازید و لوکیشن/پنل همان ردیف را به محصول وصل کنید.
5. اگر روی سرور ایلان چند instance وایرگارد دارید، ربات کانفیگهای موجود را از API می‌گیرد و ارسال می‌کند.

### مثال نام‌گذاری

- پنل: `ایلان OpenVPN` → inboundid = `openvpn` → محصول OpenVPN  
- پنل: `ایلان WireGuard` → inboundid = `wireguard` → محصول WireGuard  
- پنل: `ایلان L2TP` → inboundid = `l2tp` → محصول L2TP  
- پنل: `ایلان Cisco` → inboundid = `cisco` → محصول Cisco  
- پنل: `ایلان Multi` → inboundid = `multi` → محصول Multi  

> اگر فقط یک پنل با inboundid اشتباه یا خالی بسازید، ممکن است همه پروتکل‌ها با هم ساخته شوند یا خروجی نامرتب باشد.

## پنل Connectix (از v5.0.0، بازنویسی در v5.0.24)

سایت فروشنده: `https://seller.connectix.vip`  
صفحهٔ توکن و Swagger: `https://seller.connectix.vip/profile/api-token`

### راه‌اندازی

- نوع پنل: **Connectix** در منوی افزودن پنل
- آدرس API (املای رسمی خود کانکتیکس): `https://seller-api.connectix.vip/externel/v1`
- رمز پنل = **API Token** (Account Settings → API Token)
- پس از ذخیره، پلن‌های فعال با `GET /clients/get-enabled-plans` به‌صورت محصول در دستهٔ **کانکتیکس** ساخته می‌شوند. شناسهٔ پلن (UUID) در فیلد `note` محصول ذخیره می‌شود؛ این فیلد را دستی تغییر ندهید.
- نام محصول در ربات = فیلد **Title** پلن کانکتیکس (مثل Economic 30G)
- پلن‌هایی که در عنوانشان کلمهٔ **free** هست پلن تست‌اند؛ وارد فروشگاه و تعرفه نمی‌شوند و به دکمهٔ **اکانت تست** وصل می‌شوند.

### نحوهٔ کار با API

| کار | درخواست |
|-----|---------|
| ساخت کاربر | `POST /clients/store` و بعد `GET /clients/show?id=` برای نام کاربری، رمز و لینک ساب |
| اطلاعات و مصرف | `GET /clients/show?id=` (حجم از `active_plan`، انقضا از `expire_date`) |
| پیدا کردن شناسه از نام کاربری | `GET /clients?username=` با تطبیق دقیق |
| تمدید / افزودن پلن | `POST /clients/add-plan` با `{id, plan_id}` |

> **نکته:** هر درخواست موفق add-plan یک خرید واقعی از موجودی فروشنده است؛ ربات آن را **هرگز تکرار نمی‌کند**. اگر پاسخی نرسید، قبل از تلاش دوباره پنل کانکتیکس را بررسی کنید. خطای 403 یعنی موجودی یا دسترسی کافی نیست و 422 یعنی شناسهٔ کاربر یا پلن نامعتبر است.

> **نکته:** مسیر `/external/v1` (با املای درست انگلیسی) ۴۰۴ می‌دهد؛ حتماً `externel` باشد.

دستورهای ادمین:

```text
🔄 همگام پلن کانکتیکس
👥 کاربران کانکتیکس
cxshow USERNAME
cxadd USERNAME PLAN_ID
```

اگر پنل از قبل با آدرس قدیمی ذخیره شده:

```sql
UPDATE marzban_panel
SET url_panel = 'https://seller-api.connectix.vip/externel/v1'
WHERE type = 'connectix';
```

## چند نصب موازی (Multi-instance) — از v3.0.1

روی **یک سرور** می‌توانید چند ربات جدا نصب کنید:

| باید جدا باشد | مثال |
|---------------|------|
| مسیر نصب | `/home/mirza_vali_pro` و `/home/mirza_vali2` |
| دامنه | `bot1.example.com` و `bot2.example.com` |
| دیتابیس | نام/یوزر جدا (پیش‌فرض بر اساس نام پوشه) |
| توکن تلگرام/بله | هر ربات توکن خودش |

- هر نمونه env جدا در `/etc/mirza_vali/instances/<id>.env` دارد.
- پورت آپاچی اختصاصی جدا برای هر نمونه انتخاب می‌شود.
- در منو: گزینه **۹) List instances** — و هنگام Update/Remove اگر چند نمونه باشد، از شما می‌پرسد کدام را انتخاب کنید.
- نصب نمونهٔ دوم: گزینه **۱** با مسیر جدید (مثلاً `/home/mirza_vali2`).
